---
title: "Environment variables"
description: "Override any setting or global flag from the environment, for CI and scripts."
---

Every setting has a `TYR_*` variable, and environment variables override every settings file. `tyr config` shows when one is in effect.

## Settings

| Variable | Setting | Values |
| --- | --- | --- |
| `TYR_CHECKS_BUILD` | `checks.build` | boolean |
| `TYR_CHECKS_TEST` | `checks.test` | boolean |
| `TYR_CHECKS_LINT` | `checks.lint` | boolean |
| `TYR_CHECKS_FORMAT` | `checks.format` | boolean |
| `TYR_CHECKS_TYPECHECK` | `checks.typecheck` | boolean |
| `TYR_SEVERITY` | `severity.threshold` | `info`, `warning`, `error` |
| `TYR_REVIEW_DIFF` | `review.diff` | boolean |
| `TYR_REVIEW_LLM` | `review.llm` | boolean |
| `TYR_AGENT_PERMISSION` | `agent.permission` | `read-only`, `suggest`, `edit` |
| `TYR_NOTIFY` | `notifications.targets` | Comma-separated, or `none` |
| `TYR_MODEL` | `ai.model` | Any model id |
| `TYR_API_KEY` | `ai.apiKey` | Your key |
| `ANTHROPIC_API_KEY` | `ai.apiKey` | Used only when `TYR_API_KEY` is unset |

Booleans accept `true`/`false`, `1`/`0`, `yes`/`no` and `on`/`off`, in any case.

## Global flags

| Variable | Same as | Notes |
| --- | --- | --- |
| `TYR_QUIET` | `--quiet` | An explicit flag wins |
| `TYR_VERBOSE` | `--verbose` | Also turns on debug logging unless a log level is set |
| `TYR_JSON` | `--json` | `TYR_JSON=0` turns off an inherited `TYR_JSON=1` |
| `TYR_LOG_LEVEL` | `--log-level` | `debug`, `info`, `warn`, `error`, `silent`. The background process inherits it |

## Other

| Variable | Effect |
| --- | --- |
| `TYR_CONFIG_HOME` | Directory of the global config, instead of `~/.config/tyr` |
| `TYR_DEBUG` | `1` prints stack traces for unexpected errors |
| `NO_COLOR` | Any value turns colored output off |

## Rules

- **Empty means unset.** `TYR_API_KEY=""` is ignored, so it still falls back to `ANTHROPIC_API_KEY`. CI systems often export missing secrets as empty strings, and that should never wipe a configured value.
- **Bad values never stop Tyr.** An invalid value, such as `TYR_SEVERITY=fatal`, is ignored with a warning naming the variable. Key values never appear in warnings.

## Example: CI

```bash
export TYR_JSON=1 TYR_CHECKS_FORMAT=true TYR_SEVERITY=error
tyr init --no-gitignore
```
